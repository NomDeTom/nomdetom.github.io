Explanation

The bytes at the front of every Meshtastic LoRa frame are not protobuf. They are a plain C struct (PacketHeader) copied onto the air byte for byte, so the layout is entirely fixed: every field is present in every packet, at a fixed offset, at a fixed width. Only what follows the header — the payload — is protobuf, and it is normally encrypted, which is why the header has to stay readable in the clear by every relay.

A fixed layout has no way to say “this field is unused here”. next_hop and relay_node are a byte each and carry 0 (NO_NEXT_HOP_PREFERENCE / NO_RELAY_NODE) when there is nothing to say — the byte still goes out, and still costs airtime, on every packet that has no use for it.

The header already does a narrow version of the alternative. When hop_start is 0 — a sender older than 2.3 — the receiver treats next_hop and relay_node as invalid rather than as the value 0. Three bits already in the flags byte qualify two whole bytes; the bytes are just still sent either way.

This page is a sandbox for the other option: layouts where a field is optional or variable rather than mandatory. Give a field a presence bit in a flags byte and send the field only when the bit is set, and the empty case costs one bit instead of eight. Set those fields to Header (optional) or Header (variable) and the Size Summary separates the fixed floor — what every packet pays — from the part that only sometimes appears.

Two things to keep honest while experimenting. The bits have to come from somewhere: today’s flags byte is fully allocated (hop limit 3, want-ack 1, via-MQTT 1, hop start 3 = 8 of 8). And any change here is a wire-format break — both ends must agree — so this is for sizing the trade, not for proposing one.
