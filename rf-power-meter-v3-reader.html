USB RF Power Meter V3 Reader

Live readout, trace and capture for the V3 USB RF power meter (100 kHz – 10 GHz, STM32 + AD8317/AD8318 log detector), straight from the browser over Web Serial. It sets the V3's nine frequency/offset pages and its three sample rates. The V5 meter uses different firmware; its commands are here too, behind the V5 switch.

Back to index

Did you know: this page can be saved and used locally! Chrome and Edge allow Web Serial from a local file.

The V5 protocol notes and the approach to parsing the stream (split on the unit letter, take the last nine characters) are from LostInNovo/rf-power-meter-v5-companion (MIT), which made a useful starting point. That repo documents the V5. The V3 command set here is from the vendor's V3 manual and app, and was checked on the wire against a V3 unit.

This browser has no Web Serial API. Use Chrome or Edge on a desktop (Windows, macOS, Linux or ChromeOS). Firefox, Safari and mobile browsers do not support it.

This page is for the V3 meter. The V3 enumerates as native USB (0483:5740, "STM32 Virtual COM Port"), wraps every record as a-54300000uA, stays silent until it receives a command, and keeps its settings across a power cycle.

Have a V5 instead? Switch the model to V5 under Connection. The V5 commands come from the companion repo and have not been tested on a V5 here.

V3: the port chooser lists the STM32 Virtual COM Port. The baud rate is ignored over native USB (921600 is sent, as in the manual). A Read goes out 150 ms after connecting, because the V3 sends nothing until its first command.

V5: the port chooser lists every serial port, because the V5 uses a USB-UART bridge. The port is opened at 460800 8N1, which the bridge needs.

Rolling: the right edge is now. Pause freezes the view only; records keep arriving and nothing is lost. Fixed frame: the frame starts when you press Start frame, or, set to On threshold, at the first record at or above the level set beside it (the same level as Threshold events), with 10% of the width before the trigger. Stop freezes the frame when it is full and keeps it until you start another; Wrap sweeps like an oscilloscope, newest overwriting oldest.

Save trace CSV exports the raw records behind what is on screen, not the 50 ms bins: seq,host_time_ms,dbm. At S2 a few dozen records share each USB read's host time; use seq and the record rate for true spacing. The buffer holds about 2 million records: 10 min at S2, far longer at S1.

Capture

idle

Key the transmitter, then press Capture. The floor is the tare, or else the median of the 3 s before the window. The result is the median of the records more than the threshold above the floor. On time is the count of those records divided by the measured record rate. It is only meaningful at S2.

Each page holds a calibration frequency and an offset. The meter adds the offset to every reading, so an attenuator's value there gives power at the attenuator input. The two buttons on the meter step between pages. Read does not say which page is active: set active page to match the meter's display, so that the safety warnings use the right offset; its column is highlighted. V3 settings persist across a power cycle.

The V5 holds one setting, kept in RAM only: it powers up at 1 MHz, +0.0 dB.

The detector is broadband: the frequency picks a calibration, not a filter. Every command is checked against the full form A0868+30.6 before it is written. The short form A0868 is never sent, because on the V5 it corrupts the offset.

Sample rate (V3)

rate not set this session

Measured on a V3: S0 about 1 record/s, S1 (default) about 5/s, S2 about 2,500/s. At S2 a LoRa packet gets hundreds of records, so packets can be measured directly. The meter cannot report its rate: the page checks the measured rate 3 s after each send. S2 turns the meter's own display off, and the manual warns that commands are less reliable at S2, so resend if the check fails.

Sample period (V5)

K01–K18 set the V5's burst sample period. K is write-only, and the stream pauses about 1 s while the meter reconfigures. The V3 ignores K: use S0/S1/S2 there.

Threshold events

startdurationn ÷ ratepeakn

An event opens when a record reaches the level, and closes after 150 ms below level − 1 dB. The newest 5,000 events are kept. Duration is by host arrival time; n ÷ rate is the record count over the measured rate. At S1 a short packet is caught only by chance; use S2.

Record

0 rows

For runs longer than the trace buffer: every record from Start to Stop, as seq,host_time_ms,dbm. Records that arrive in one USB read share a time. Capped at 3 million rows, about 20 minutes at S2. For anything shorter, Save trace CSV does the same after the fact.

Raw command
—

Known commands go straight out: Read, full-form page commands, S0–S2, K01–K18. A command starting with a page letter A–I must be the full form. Anything else asks first, because an unknown command could overwrite settings, and on the V3 settings persist. Press Read beforehand so the current pages are on record.

          How the V3 meter talks

          
Getting started

          
    
            
  • 
              Plug the meter in. On Windows 10 and later it uses the built-in USB serial driver.
              On Linux it appears as /dev/ttyACM*, and your user needs access to
              it (usually the dialout group).
            
    • 
            
  • 
              Close anything else holding the port, such as the vendor app, a script or a serial
              monitor. Only one program can open it at a time.
            
    • 
            
  • 
              Press Connect and pick "STM32 Virtual COM Port". The page sends
              Read, the pages table fills, and records start.
            
    • 
            
  • 
              Keep the detector input below about +12 dBm; above that, damage is
              instant. The linear range is about −50 to −5 dBm, and readings compress above
              −5 dBm. Use an attenuator, and put its value in the page offset.
            
    • 
          


          
Record format

          

            ASCII records, already calibrated to dBm on the meter. The V3 wraps each one in
            a … A:
          

          
a-54300000uA   =  −54.3 dBm, watts field 000.00 µW
a+25838194mA   =  +25.8 dBm, 381.94 mW
 │└┤│└─┬─┘│
 │ │ │  │  └ unit and terminator: u = µW, m = mW, w = W
 │ │ │  └ watts field, DDD.dd
 │ │ └ tenths of a dB
 │ └ whole dB
 └ sign

          
    
            
  • 
              Split on any of u, m or w. A parser that
              splits only on u stops working at 0 dBm and above.
            
    • 
            
  • 
              Take the last nine characters before the terminator: sign plus eight digits. This
              ignores the a/A wrapping on the V3 and the block
              markers on the V5.
            
    • 
            
  • 
              The watts field reads 000.00 below about 1 µW. Recompute watts from
              dBm instead.
            
    • 
          


          
V3 commands

          
Each ends in CRLF and goes out as one write, with no stray bytes before it.

          

            

              
commandeffect

              
                

                  Read
                  
                    Reply inside the stream: R followed by all nine pages, each
                    <MHz:4><±dd.d>, e.g.
                    R0868+30.6 0200+00.0 … 6000+00.0. Also starts the stream if the
                    meter is silent. The first Read after a page command is sometimes swallowed;
                    retry after about 1.5 s.
                  
                

                

                  A0868+30.6 … I…
                  
                    Set page A … I: calibration frequency in MHz and offset in dB. All nine can
                    go in one line, concatenated A to I.
                  
                

                

                  S0 / S1 / S2
                  
                    Sample rate low / medium (default) / high. Measured 1.0, 5.0 and 2,510
                    records/s. At S2 the meter's display turns off.
                  
                

              
            

          


          
V3 behaviour found on the bench

          
    
            
  • 
              Silent at open. Nothing arrives until the first command. Raising DTR does
              not start it; only a write does.
            
    • 
            
  • 
              Settings persist. Pages survive unplugging, so the value you see on first
              contact is the last saved setting, not a default.
            
    • 
            
  • 
              Every write pauses the stream for about 0.5 s. Polling it (even bare CRLFs)
              slows the stream down rather than speeding it up, so don't poll it.
            
    • 
            
  • 
              At S1 records come on a steady tick of about 190 ms. Each record arrives in its own
              USB read, so host arrival time is a fair timestamp.
            
    • 
            
  • 
              At S2 a 624 ms LoRa packet (SF10, BW250) gave about 1,560 records. The rise to
              within 1 dB of peak took under 0.5 ms, and the envelope was flat to 0.1 dB.
            
    • 
            
  • 
              The V5's K01–K18 do nothing on the V3, and are not in the
              V3 manual or app.
            
    • 
            
  • 
              With the input open, the floor reads about −54.5 dBm on the 868 MHz calibration and
              about −57 dBm on the 2400 MHz one. Each page's calibration shifts the floor.

Minimal Python reader

          

            The same parse in a few lines of pyserial (pip install pyserial).
            Change the port name to yours.
          

          
import re
import serial

REC = re.compile(rb"([+-])(\d\d)(\d)\d{5}[umw]")

port = serial.Serial("COM3", 921600, timeout=0.1)  # Linux: "/dev/ttyACM0"
port.write(b"Read\r\n")  # the V3 is silent until its first command
port.write(b"S1\r\n")    # S0 low, S1 medium, S2 high
buf = b""
while True:
    buf += port.read(4096)
    for m in REC.finditer(buf):
        dbm = int(m[2]) + int(m[3]) / 10
        print(-dbm if m[1] == b"-" else dbm)
    # keep only the unfinished record after the last terminator
    cut = max(buf.rfind(b"u"), buf.rfind(b"m"), buf.rfind(b"w"))
    buf = buf[cut + 1:] if cut >= 0 else buf[-64:]

          

            Send one command per write, and leave a few hundred ms between commands. At S2,
            read in large chunks (for example port.read(65536)) to keep up with the
            stream.
